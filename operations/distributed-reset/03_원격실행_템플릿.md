# 03. 원격실행 템플릿

질문 포인트:
- 로컬에서 바로 할 수 있나?
- 분산 라즈베리인데 어디서 실행해야 하나?

정답:
- 명령 자체는 각 서버에서 실행되어야 한다.
- 다만 운영자 PC에서 SSH로 각 서버에 접속해서 실행하면 된다.

---

## 2) 한 줄 원격 실행 예시

Detection 중지:

ssh pi@192.168.0.130 "cd ~/OTT_Testbad/deploy/server4 && docker compose stop detection-engine"

Elasticsearch 인덱스 삭제:

action.destructive_requires_name=true 환경에서는 wildcard DELETE가 막힌다.
아래처럼 먼저 실제 인덱스명을 조회한 뒤, 이름으로 삭제한다.

ssh pi@192.168.0.120 "for idx in $(curl -s 'http://localhost:9200/_cat/indices/scrubber-nginx-*,filebeat-*,.ds-scrubber-nginx-*,.ds-filebeat-*?h=index' | tr -d '\r'); do curl -s -X DELETE \"http://localhost:9200/$idx?ignore_unavailable=true\"; echo; done"

주의:
- .ds-scrubber-nginx-* 가 write index라면 위 명령으로 직접 삭제되지 않는다.
- 이 경우 반드시 data stream을 먼저 삭제해야 한다.

data stream 먼저 삭제 (server3):

ssh pi@192.168.0.120 "for ds in $(curl -s 'http://localhost:9200/_data_stream' | grep -o '\"name\":\"[^\"]*\"' | cut -d '\"' -f4 | egrep 'scrubber|filebeat' | tr -d '\r'); do curl -s -X DELETE \"http://localhost:9200/_data_stream/$ds\"; echo; done"

그 다음 남은 .ds 인덱스 삭제 (server3):

ssh pi@192.168.0.120 "for idx in $(curl -s 'http://localhost:9200/_cat/indices?h=index&expand_wildcards=all' | egrep '^\\.ds-scrubber-nginx|^\\.ds-filebeat' | tr -d '\r'); do curl -s -X DELETE \"http://localhost:9200/$idx?ignore_unavailable=true\"; echo; done"

Neo4j 그래프 삭제:

ssh pi@192.168.0.120 "docker exec -i ott-neo4j cypher-shell -d neo4j -u neo4j -p ott_detection_2025 'MATCH (n) DETACH DELETE n;'"

PostgreSQL 활동 테이블 비우기:

ssh pi@192.168.0.100 "docker exec -i ott-postgres psql -U ott_user -d ott_auth -v ON_ERROR_STOP=1 -c 'TRUNCATE TABLE watch_history, sessions, audit_logs RESTART IDENTITY CASCADE;'"

Detection 재기동:

ssh pi@192.168.0.130 "cd ~/OTT_Testbad/deploy/server4 && docker compose up -d --force-recreate detection-engine"

## 2.5) 데이터가 다시 생길 때 추가로 해야 할 것 (중요)

증상:
- ES 인덱스를 지웠는데 Kibana에 예전 시각 데이터가 다시 보임

원인:
- Filebeat offset을 리셋하면 기존 access.log를 처음부터 다시 읽는다.
- 즉, 원본 로그 파일을 비우지 않으면 과거 데이터가 재적재된다.

조치:
1. detection 중지 (server4)
2. edge filebeat 중지 (4대)
3. edge 원본 로그 파일 비우기 (4대)
4. ES 인덱스 삭제 (server3)
5. Neo4j 삭제 (server3)
6. filebeat 재기동 후 detection 재기동

실행 명령 (운영자 PC에서 순서대로 그대로 실행):

1) detection 중지 (server4)

ssh pi@192.168.0.130 "cd ~/OTT_Testbad/deploy/server4; docker compose stop detection-engine"

2) edge filebeat 중지 (4대)

ssh pi@192.168.0.111 "cd ~/OTT_Testbad/deploy/edge-kr; docker compose stop filebeat"
ssh pi@192.168.0.112 "cd ~/OTT_Testbad/deploy/edge-jp; docker compose stop filebeat"
ssh pi@192.168.0.113 "cd ~/OTT_Testbad/deploy/edge-sg; docker compose stop filebeat"
ssh pi@192.168.0.114 "cd ~/OTT_Testbad/deploy/edge-us; docker compose stop filebeat"

3) edge 원본 로그 파일 비우기 (4대)

ssh pi@192.168.0.111 "docker exec -i edge-kr sh -lc ': > /var/log/nginx/access.log; : > /var/log/nginx/error.log'"
ssh pi@192.168.0.112 "docker exec -i edge-jp sh -lc ': > /var/log/nginx/access.log; : > /var/log/nginx/error.log'"
ssh pi@192.168.0.113 "docker exec -i edge-sg sh -lc ': > /var/log/nginx/access.log; : > /var/log/nginx/error.log'"
ssh pi@192.168.0.114 "docker exec -i edge-us sh -lc ': > /var/log/nginx/access.log; : > /var/log/nginx/error.log'"

4) ES 인덱스 삭제 (server3)

ssh pi@192.168.0.120 "for idx in $(curl -s 'http://localhost:9200/_cat/indices/scrubber-nginx-*,filebeat-*,.ds-scrubber-nginx-*,.ds-filebeat-*?h=index' | tr -d '\r'); do curl -s -X DELETE \"http://localhost:9200/$idx?ignore_unavailable=true\"; echo; done"

5) Neo4j 그래프 삭제 (server3)

6) filebeat 재기동 후 detection 재기동

ssh pi@192.168.0.111 "cd ~/OTT_Testbad/deploy/edge-kr; docker compose up -d filebeat"
ssh pi@192.168.0.112 "cd ~/OTT_Testbad/deploy/edge-jp; docker compose up -d filebeat"

ssh pi@192.168.0.130 "cd ~/OTT_Testbad/deploy/server4; docker compose up -d --force-recreate detection-engine"

## 4) 실수 방지 체크

1. 분산 환경에서는 localhost가 서버마다 다르다.
2. ES/Neo4j 명령은 반드시 server3에서 실행한다.
3. Postgres 명령은 반드시 server1에서 실행한다.
4. detection 명령은 반드시 server4에서 실행한다.
5. edge/filebeat 명령은 해당 edge 장비에서 실행한다.

## 5) 초기화 확인 명령

ES 도큐먼트 수 확인 (server3):

ssh pi@192.168.0.120 "curl -s 'http://localhost:9200/scrubber-nginx-*,filebeat-*,.ds-scrubber-nginx-*,.ds-filebeat-*/_count?ignore_unavailable=true&expand_wildcards=all'"

Neo4j 노드 수 확인 (server3):

ssh pi@192.168.0.120 "docker exec -i ott-neo4j cypher-shell -d neo4j -u neo4j -p ott_detection_2025 'MATCH (n) RETURN count(n);'"

PostgreSQL 활동 테이블 확인 (server1):

ssh pi@192.168.0.100 "docker exec -i ott-postgres psql -U ott_user -d ott_auth -c 'SELECT (SELECT count(*) FROM watch_history) AS watch_history_cnt, (SELECT count(*) FROM sessions) AS sessions_cnt, (SELECT count(*) FROM audit_logs) AS audit_logs_cnt;'"
