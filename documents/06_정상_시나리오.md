# 06. 정상 시나리오 (N1~N7)

> 운영 참고 (2026-04-16): 본 문서는 실험 시나리오 설계 문서다. 현재 실제 트래픽 생성/장비 운용 기준은 `11`, `12`, `13`, `15` 문서를 우선한다.

---

## 설계 원칙

정상 시나리오는 모델의 **오탐(False Positive)을 방지**하기 위해 다양해야 한다.
실제 사용자의 시청 행동은 매우 다양하므로, 단일 "정상 패턴"이 아닌
여러 유형의 정상을 학습시켜야 한다.

---

## N1: 일반 시청 (PC, 처음부터 끝까지)

**사용자 프로필**: 집에서 PC로 영화를 처음부터 끝까지 보는 사용자

| 항목 | 값 |
|------|-----|
| 디바이스 | Windows PC + Chrome |
| 콘텐츠 | movie_001 (12분, 180 세그먼트) |
| 시청 범위 | seg_0001 ~ seg_0180 (전체) |
| 요청 간격 | 평균 6.0초, 표준편차 0.3초 |
| 해상도 | 720p 고정 |
| Referer | http://myott.com/watch/movie_001 |
| 매니페스트 | master.m3u8 → 720p/playlist.m3u8 |
| browse_content 요청 | 있음 (콘텐츠 상세 조회 후 재생) |

**구현 (Python)**

```python
import requests, time, random

class NormalViewer:
    def __init__(self, api_url, email, password):
        self.api = api_url
        self.session = requests.Session()
        self.login(email, password)
    
    def login(self, email, password):
        r = self.session.post(f"{self.api}/auth/login",
                              json={"email": email, "password": password})
        self.jwt = r.json()["access_token"]
        self.session.headers["Authorization"] = f"Bearer {self.jwt}"
    
    def browse_content(self, content_id):
        """정상 사용자는 콘텐츠 상세 조회 후 재생하는 경우가 많음"""
        self.session.get(f"{self.api}/browse/content/{content_id}")
        time.sleep(random.uniform(2, 8))  # 결과 살펴보는 시간
    
    def watch_sequential(self, content_id, resolution="720p"):
        # 재생 시작 요청 → CDN Token 획득
        r = self.session.post(f"{self.api}/playback/start",
                              json={"content_id": content_id})
        manifest_url = r.json()["manifest_url"]
        
        # 매니페스트 요청
        self.session.get(manifest_url)
        time.sleep(random.uniform(0.3, 0.8))
        
        # 세그먼트 순차 요청
        base_url = manifest_url.rsplit("/", 1)[0]
        for seg_num in range(1, 181):
            seg_url = f"{base_url}/{resolution}/seg_{seg_num:04d}.ts"
            self.session.get(seg_url)
            
            # 자연스러운 jitter (핵심!)
            interval = random.gauss(6.0, 0.3)
            interval = max(5.2, min(7.0, interval))
            time.sleep(interval)
```

## N2: 탐색(Seek)이 포함된 시청 (모바일)

**사용자 프로필**: 모바일에서 영상을 보다가 앞뒤로 건너뛰는 사용자

| 항목 | 값 |
|------|-----|
| 디바이스 | iPhone + Safari |
| 콘텐츠 | movie_002 (8분, 120 세그먼트) |
| 시청 패턴 | seg_001~030 → [점프] → seg_090~120 → [점프] → seg_050~070 |
| 요청 간격 | 시청 중 6.0±0.4초, 탐색 시 1~3초 공백 |
| 해상도 | 720p |

**탐색 동작의 로그 패턴**

```
seg_030 요청 (14:25:00.000)
[탐색 — 1.5초 공백]
playlist.m3u8 재요청 (14:25:01.500)  ← 탐색 시 매니페스트 재요청
seg_090 요청 (14:25:02.200)          ← 점프
seg_091 요청 (14:25:06.100)
seg_092 요청 (14:25:10.300)
...
```

핵심: 세그먼트 번호에 "점프"가 있고, 점프 직전에 매니페스트 재요청이 발생.
이건 정상 행동이므로 모델이 이걸 공격으로 판단하면 오탐.

## N3: ABR 화질 변경

**사용자 프로필**: Smart TV에서 시청, 네트워크 상태에 따라 화질이 자동 변경

| 항목 | 값 |
|------|-----|
| 디바이스 | Smart TV (Tizen) |
| 시청 패턴 | 480p(5개) → 720p(30개) → 1080p(100개) → 720p(20개) → 1080p(끝까지) |

**로그 패턴**

```
/content/movie_001/480p/seg_0001.ts   (bytes: 500KB)
/content/movie_001/480p/seg_0002.ts
...
/content/movie_001/720p/seg_0006.ts   (bytes: 1.2MB) ← 해상도 전환
/content/movie_001/720p/seg_0007.ts
...
/content/movie_001/1080p/seg_0036.ts  (bytes: 2.5MB) ← 해상도 전환
```

핵심: 동일 세그먼트 번호를 다른 해상도로 중복 요청할 수 있음 (전환 시).
bytes_sent가 해상도에 따라 크게 변동.

## N4: 일시정지 후 재개

**사용자 프로필**: 중간에 일시정지하고 나중에 이어보는 사용자

| 항목 | 값 |
|------|-----|
| 시청 패턴 | seg_001~015 → [5분 공백] → seg_016~040 → [30분 공백] → 토큰 갱신 → seg_041~ |

**로그 패턴**

```
seg_015 요청 (14:24:00)
[5분간 요청 없음]
seg_016 요청 (14:29:00)
...
seg_040 요청 (14:30:36)
[30분간 요청 없음]
POST /api/playback/start (15:00:36)  ← 토큰 만료로 재요청
seg_041 요청 (15:00:37)  ← 새 토큰으로 이어서
```

핵심: 긴 공백 후 세션 재개. 30분 이상 공백 시 토큰 갱신 발생.
이 패턴을 공격(봇의 간헐적 동작)과 구분해야 함.

## N5: 멀티 디바이스 사용자

**사용자 프로필**: 집에서 PC로 보다가 외출하며 모바일로 이어보기

| 항목 | 값 |
|------|-----|
| 세션 1 | PC (IP: 192.168.0.11), seg_001~075, Edge-KR |
| [30분 간격] | |
| 세션 2 | Mobile (IP: 192.168.0.11 → LTE IP로 변경), seg_076~, Edge-KR |

**로그 패턴**

세션 1과 세션 2는 **시간적으로 겹치지 않음**. 동일 계정, 다른 세션 ID, 
다른 디바이스, IP가 다를 수 있음. 하지만 세그먼트 번호가 첫 세션의 
마지막에서 두 번째 세션이 이어감.

공격(A1)과의 차이: A1은 동시에 여러 IP에서 접근, N5는 순차적으로 IP 변경.

## N6: 가족 동시 시청 (같은 가구)

**사용자 프로필**: 가족 2명이 같은 집에서 서로 다른 콘텐츠 동시 시청

| 항목 | 프로필 A | 프로필 B |
|------|---------|---------|
| 디바이스 | TV | 태블릿 |
| 콘텐츠 | movie_001 | movie_003 |
| IP | 192.168.0.11 (동일) | 192.168.0.11 (동일) |
| 세션 | sess_family_a | sess_family_b |
| Edge | edge-kr | edge-kr |

**로그 패턴**

두 세션이 동시에 활성. 같은 IP, 같은 계정(다른 프로필), 다른 콘텐츠.
동시 스트림 수 = 2 (Standard/Premium 플랜 범위 내).

공격과의 차이:
- A1은 동일 콘텐츠를 다수 IP에서 동시 접근
- N6는 다른 콘텐츠를 같은 IP에서 동시 접근

## N7: 라이브 스포츠 정상 시청

**사용자 프로필**: 정상 구독자가 라이브 채널(live_001)을 연속 시청

| 항목 | 값 |
|------|-----|
| 디바이스 | PC + Chrome |
| 콘텐츠 | live_001 (LIVE) |
| 시청 시간 | 30분~2시간 |
| 해상도 | 1080p 중심, 네트워크 상황에 따라 720p 전환 |

핵심 로그 특징:

1. `playlist.m3u8` 요청이 3~6초 간격으로 반복
2. 세그먼트 번호가 최신 구간에서 단조 증가
3. DVR 미구현 기준으로 과거 세그먼트 탐색 패턴이 거의 없음

정상 판별 포인트:

- 라이브는 매니페스트 반복 요청이 많아도 공격으로 보지 않는다.
- 인기 경기 시점의 동시 시청자 급증 자체는 정상일 수 있다.
