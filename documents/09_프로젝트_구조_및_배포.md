추가 운영 변경(14 반영):

- 서버#1/로컬에 `live-encoder` 서비스 추가
- 플랫폼 웹에 콘텐츠(VOD)/라이브(LIVE) 구분 및 영상관리 페이지(`/manage`) 추가
- 콘텐츠 메타데이터에 `contentType`, `availableResolutions(1080p/720p)` 운영 항목 추가
- `/manage`의 VOD `sourceVideo` 업로드 시 `scrubber/api`가 FFmpeg로 `origin/hls/<hls_path>/`에 1080p/720p HLS와 `master.m3u8`를 자동 생성
- `/manage`에서 `target_duration_min`(또는 API `target_duration_sec`)를 지정하면, 짧은 원본 영상도 업로드 시점에 반복 확장해 목표 길이 VOD로 생성 가능

## 4. 실행 엔트리포인트

### 4.1 로컬 단일 머신

```powershell
docker compose -f docker-compose.lab.yml up -d --build
```

### 4.2 물리 분산

각 장비에서 해당 폴더로 이동 후:

```bash
docker compose up -d --build
```

대상 폴더:

- `deploy/server1`
- `deploy/server3`
- `deploy/server4`
- `deploy/edge-kr`
- `deploy/edge-jp`
- `deploy/edge-sg`
- `deploy/edge-us`

## 5. 현재 데이터 흐름 기준

1. 사용자 로그인/재생 시작
- Web(`origin/web`) -> Edge Gateway(`/api`) -> API(`scrubber/api`) -> Signed URL 발급

2. HLS 요청 검증
- Edge(OpenResty + `scrubber/lua/auth_check.lua`)가 `/api/playback/verify`로 토큰 검증

3. 로그 수집
- Edge Nginx JSON 로그(`/api`, `/hls`) -> Filebeat -> Elasticsearch(`scrubber-nginx-*`)

4. 탐지 적재
- 서버#4 Detection(`LOG_SOURCE=elasticsearch`)이 ES poll -> Neo4j(`neo4j` DB) 적재

5. 로컬 단일 머신 모드 예외
- `docker-compose.lab.yml`에서는 Detection이 공유 볼륨 로그(`/var/log/scrubber`)를 직접 읽는 file 모드로 동작

운영 주의:
- 사용자 API 트래픽이 Edge를 경유하지 않고 `:3001`으로 직접 들어가면
  `playback_start`, `browse_content`가 탐지 그래프에 누락될 수 있다.

## 6. 제거/정리된 구식 내용

이전 버전의 09 문서에는 현재 저장소에 없는 설계 전용 경로와 스크립트 예시가 포함되어 있었다.
아래 항목들은 운영 기준에서 제거했다.

- `shared/`, `server-api/`, `server-origin/`, `server-edge/`, `server-analysis/`, `client/` 중심 가상 트리
- `deploy/run_experiment.sh` 등 저장소에 없는 자동화 스크립트 기준 절차
- `server2` 활성 운용 가정

해당 내용은 설계 아이디어 기록으로만 의미가 있으며, 현재 실행 기준으로 사용하면 배포 오류를 유발할 수 있다.
