# 08. 탐지 모델 실험 설계

> 운영 참고 (2026-04-16): 본 문서는 탐지 모델 비교 실험 설계 문서다. 실제 배포/수집/복구 절차는 `10`, `11`, `12`, `13`, `15` 문서를 우선한다.

---

## 1. 실험 목표

> 동일한 OTT 불법 사용자 탐지 데이터셋(정상 N1~N7 + 공격 A1~A6)에 대해 규칙 기반, 전통 ML, GNN을 공정하게 비교하여
> 각 방법의 탐지 가능 범위와 한계를 밝힌다.

핵심: "GNN이 최고"를 증명하는 것이 아니라
"어떤 공격 유형에 어떤 방법이 적합한가"를 밝히는 것.

## 2. 비교 대상 모델

### 2.1 규칙 기반 (Rule-Based Baseline)

| 규칙 | 임계값 | 탐지 대상 |
|------|--------|---------|
| 로그인 시도 분당 N회 초과 | 시스템 기준치 (예: 60/min) | A1 |
| 동일 계정 동시 세션 수 > max_streams | 플랜별 (1/2/4) | A3 |
| 동일 토큰 IP fan-out > 3 | 토큰당 고유 IP 수 | A3 |
| Referer가 비정상 도메인 | 화이트리스트 기반 | A3, A6 |
| token_edge_match = false | Boolean | A3 |
| User-Agent가 비브라우저 | 블랙리스트 (VLC, Kodi, FFmpeg 등) | A3, A5-B, A6 |
| has_manifest = false (세그먼트 직행) | Boolean | A5-B |
| 이벤트 시작 구간 동시 접근 급증 | 이벤트 윈도우 집계 임계값 | A6 (단순형) |
| 요청 간격 표준편차 < 0.05초 | session-level interval_stddev | A5-B |

정합성 원칙:

1. A2, A4는 규칙 기반 정탐의 주 대상에서 제외한다.
2. A2, A4는 ML/GNN 기반 관계 패턴 분석에서 우위를 검증한다.

### 2.2 전통 ML

| 모델 | 라이브러리 | 비고 |
|------|---------|------|
| Random Forest | scikit-learn | 앙상블 기반 |
| XGBoost | xgboost | 그래디언트 부스팅 |
| LSTM | PyTorch | 시퀀스 기반 (요청 순서) |

### 2.3 GNN

| 모델 | 라이브러리 | 특징 |
|------|---------|------|
| R-GCN | PyTorch Geometric | 이종 그래프 (다중 관계 타입) |
| GAT | PyTorch Geometric | 어텐션 기반 이웃 집계 |
| GraphSAGE | PyTorch Geometric | 샘플링 기반 (확장성) |

### 2.4 재설계 공격 체계 반영 (A1~A6)

공격 시나리오 체계는 `07` 문서 기준으로 A1~A6으로 정렬한다.

핵심 반영 포인트:

1. 학습/평가 대상 공격 라벨: A1, A2, A3, A4, A5-B, A6
2. A5 경로 A(DRM 복호화 후 외부 재배포)는 CDN 로그 기반 관측 불가 시나리오로 분리
3. 라이브 매니페스트 폴링 주기/정밀도 feature는 A6 탐지에 반영
4. GNN 우위 검증 핵심 시나리오는 A2, A4로 정의

## 4. GNN 입력 설계

### 4.1 노드 Feature 벡터

| 노드 타입 | Feature | 차원 |
|---------|---------|------|
| Account | plan_type (one-hot 3), total_sessions_24h, unique_ips_24h, has_browse_content_request | 6 |
| Session | duration, avg_interval, interval_stddev, has_manifest, total_requests, concurrent_sessions | 6 |
| Token | remaining_sec, total_duration, edge_match | 3 |
| ClientIP | asn_type (one-hot 3), region (one-hot 4) | 7 |
| Edge | edge_id (one-hot 4) | 4 |
| Content | type (one-hot 2), concurrent_viewers, viewer_start_time_std | 4 |
| Device | device_type (one-hot 5), ua_is_browser, ua_is_media_player, ua_is_bot | 8 |
| Referrer | is_legitimate, referer_empty_ratio, external_domain_flag | 3 |

구성 메모:

1. Segment, Request 노드는 규모가 커서 기본 실험 입력에서는 제외한다.
2. 해당 정보는 Session 집계 feature(3장)와 관계 feature(4.2)로 반영한다.

### 4.2 Edge Feature (관계 속성)

| 관계 | Feature |
|------|---------|
| HAS_TOKEN | issued_at (시간 임베딩) |
| CREATES_SESSION | - |
| FROM_IP | first_seen, last_seen, duration |
| TARGETS_CONTENT | request_kind, request_timestamp |
| MAKES_REQUEST | sequence_num, interval_to_prev |

### 4.3 그래프 분류 Task

```
입력: 세션 중심 서브그래프 (Session 노드 + 1-hop 이웃)
출력: Binary (normal=0 / attack=1) 또는 Multi-class (normal/A1/A2/A3/A4/A5/A6)

학습 방식:
1. 세션별 서브그래프 추출
2. GNN으로 노드 임베딩 학습
3. Session 노드의 최종 임베딩으로 분류
4. Cross-entropy loss

또는 그래프 레벨 분류:
1. 시간 윈도우(5분) 단위로 전체 그래프 스냅샷
2. 그래프 임베딩 (readout/pooling)
3. 그래프 전체를 normal/attack 분류
→ A2, A4처럼 여러 세션의 관계를 봐야 하는 시나리오에 적합
```

## 5. 실험 프로토콜

### 5.1 데이터 분할

```
전체 데이터: 2,900 세션 (정상 1,450 + 공격 1,450)

Train : Validation : Test = 60 : 20 : 20
- Train: 1,740 세션
- Val: 580 세션
- Test: 580 세션

Stratified Split: 각 시나리오(N1~N7, A1~A6)의 비율이
모든 Split에서 동일하게 유지되도록 층화 추출한다.

추가 원칙: A5 경로 A는 관측 불가 한계 시나리오로 별도 기술하고,
supervised 분류 라벨에는 포함하지 않는다.
```

### 5.2 평가 지표

| 지표 | 수식 | 중요도 | 목표 |
|------|------|-------|------|
| Precision | TP / (TP+FP) | 최고 | >95% (오탐 최소화) |
| Recall | TP / (TP+FN) | 높음 | >90% |
| F1-Score | 2·P·R / (P+R) | 높음 | >92% |
| FPR | FP / (FP+TN) | 최고 | <1% |
| 시나리오별 Recall | 각 A1/A2/A3/A4/A5-B/A6별 | 핵심 | GNN 우위 입증 |
| Inference Time | ms/session | 중요 | <100ms |
| Training Time | 분 | 참고 | |

### 5.3 실험 변수

| 실험 | 변수 | 목적 |
|------|------|------|
| Exp 1 | 탐지 방법 (규칙/RF/XGB/LSTM/R-GCN/GAT/SAGE) | 메인 비교 |
| Exp 2 | 토큰 보안 수준 (약/중/강) | 보안 설정별 탐지 필요성 |
| Exp 3 | 정상:공격 비율 (9:1, 7:3, 5:5) | 클래스 불균형 영향 |
| Exp 4 | 그래프 크기 (1-hop vs 2-hop 서브그래프) | GNN depth 영향 |
| Exp 5 | Feature ablation | 어떤 feature가 가장 중요한지 |

## 6. 논문 예상 결과 및 결론 프레이밍

### 6.1 예상 결과

```
[전체 F1-Score]
규칙 기반: 72~80% (A1, A3, A6 단순형은 강하지만 A2, A4는 취약)
Random Forest: 85~88%
XGBoost: 86~89%
LSTM: 83~86%
GAT: 88~92%
R-GCN: 87~91%
GraphSAGE: 86~90%

[시나리오별 Recall — 핵심 결과]
         규칙  RF   XGB  LSTM  GAT
A1       99%  99%  99%  99%  99%   ← 모두 탐지 (GNN 우위 없음)
A2       10%  65%  68%  75%  88%   ← GNN 우위 명확
A3       95%  85%  87%  82%  86%   ← 규칙 기반 우위 (단순형)
A4        5%  50%  55%  45%  78%   ← GNN 우위 가장 명확
A5-B     55%  80%  82%  79%  81%   ← 앱 역공학 직접 접근은 ML/GNN 유사
A6       70%  86%  88%  81%  89%   ← 라이브 이벤트 집계에서 GNN 근소 우위

※ A5-A(복호화 후 외부 재배포)는 CDN 로그 기반 탐지 모델 평가에서 제외(N/A)
```

### 6.2 논문 결론 프레이밍

```
1. 실험에서 정의한 단순 공격군(예: A1, A3, 일부 A6)은
   규칙 기반 방법으로도 높은 탐지율을 달성할 수 있다.

2. 그러나 토큰 로테이션(A2)과 정상 모방 분산(A4) 같은
   관계 기반 회피 공격에서는 규칙 기반과 전통 ML 모두 한계를 보이며,
   GNN이 10~25%p 높은 탐지율을 달성한다.

3. GNN의 우위는 "개별 세션이 아닌 세션 간 관계 구조"에서
   이상 패턴을 자동으로 학습하는 능력에서 기인한다.

4. 그러나 Residential Proxy 릴레이(A4)의 완전 위장 사용 등
   CDN 로그만으로는 근본적으로 탐지 불가능한 공격 유형이 존재하며,
   이에 대해서는 포렌식 워터마킹 등 보완적 기술이 필요하다.

5. 실용적 관점에서, 규칙 기반 + ML을 1차 필터로 사용하고
   GNN을 2차 정밀 탐지로 사용하는 하이브리드 접근이 최적이다.
```

## 7. 연구 일정 (수정안)

| 기간 | 작업 | 산출물 |
|------|------|--------|
| 1~2월 | 물리 실증랩 구축, 네트워크 설정 | 동작하는 OTT 플랫폼 |
| 2~3월 | 토큰 인증 구현, 로그 파이프라인 | 로그 수집 시스템 |
| 3~4월 | 정상 시나리오 스크립트 개발 + 데이터 수집 | N1~N7 데이터 |
| 4~5월 | 공격 시나리오 스크립트 개발 + 데이터 수집 | A1~A6 데이터 |
| 5~6월 | 지식그래프 구축, Feature 추출 | Neo4j 그래프, Feature CSV |
| 6~7월 | ML/GNN 모델 학습 및 비교 실험 | 실험 결과 |
| 7~8월 | 추가 실험 (ablation, robustness) | 보완 결과 |
| 8~9월 | 논문 작성 및 제출 | 최종 논문 |
