# 12. 라즈베리 개별 운용 설명서 (Pi-01 ~ Pi-10)

이 문서는 `11_라즈베리_및_서버_분산배포_매뉴얼.md`의 Pi 파트를 장비별로 분해한 **실행 카드**다.
각 Pi 담당자는 본인 장비 섹션만 따라 수행하면 된다.

---

## 0. 공통 기준

- API/Web 서버: `192.168.0.100`
- Edge-KR: `192.168.0.111`
- Edge-JP: `192.168.0.112`
- Edge-SG: `192.168.0.113`
- Edge-US: `192.168.0.114`
- 관측/저장 서버: `192.168.0.120`
- 서브넷: `192.168.0.0/24`
- 기본 게이트웨이: `192.168.0.1`
- DNS: `8.8.8.8`
- 클라이언트 API 기본 진입점: Edge URL `/api` (예: `http://192.168.0.111/api`)

Edge Pi(4대) 개별 구성은 `13_엣지_라즈베리_개별_운용_설명서.md`를 참고한다.

역할 구분:

- `정상`: 일반 사용자 재생 트래픽 생성
- `공격자(예약)`: 현재는 정상 절차로 baseline 확보, 이후 공격 자동화 코드 투입 예정

---

## 1. 공통 1회 설정 (모든 Pi)

모든 Pi에서 최초 1회 실행:

```bash
sudo apt update
sudo apt install -y curl ca-certificates
```

헬스체크 공통 명령:

```bash
ping -c 3 192.168.0.100
ping -c 3 192.168.0.111
ping -c 3 192.168.0.112
ping -c 3 192.168.0.113
ping -c 3 192.168.0.114
ping -c 3 192.168.0.120
curl http://192.168.0.111/health
curl http://192.168.0.111/api/content/list
# 필요 시 내부 API 헬스 확인
curl http://192.168.0.100:3001/health
```

주의:

- `/health`는 서비스 생존 확인용이다.
- Edge Nginx 설정상 `/health` 요청은 access log에 남지 않으므로 Kibana/Detection 검증용 트래픽으로는 사용하지 않는다.

정상 트래픽 생성 공통 절차:

1. 브라우저(Chromium)에서 `http://192.168.0.100:5173` 접속
2. 계정 로그인
3. 콘텐츠 1개 이상 재생 시작
4. 5~10분 유지 후 다른 콘텐츠로 전환
5. 로그 유입 확인이 필요하면 Edge URL에 일반 경로 요청을 3~5회 발생
	- 예: `for i in 1 2 3 4 5; do curl -s "http://192.168.0.111/?probe=$i" >/dev/null; done`

운영 주의:
- 브라우저 Network 탭에서 API 호출 Host가 Edge(예: `192.168.0.111`)인지 확인한다.
- API를 `:3001`로 직접 호출하면 `browse_content`/`playback_start` 탐지 신호가 누락될 수 있다.

라이브 시나리오(N7) 트래픽 생성:

1. 플랫폼에서 `live_001` 선택
2. 최소 10분 이상 연속 재생 유지
3. `playlist.m3u8` 요청이 3~6초 간격으로 반복되는지 Kibana에서 확인

## 3. Pi별 실행 카드

아래 절차에서 네트워크 인터페이스가 `eth0`가 아닌 장비는 `wlan0`로 바꿔 적용한다.

### 3.1 Pi-01 (KR, 정상)

```bash
sudo hostnamectl set-hostname pi-01
sudo tee /etc/dhcpcd.conf > /dev/null <<'EOF'
interface eth0
static ip_address=192.168.0.11/24
static routers=192.168.0.1
static domain_name_servers=8.8.8.8
EOF
sudo systemctl restart dhcpcd
```

검증: 공통 헬스체크 명령 실행 후 웹 로그인/재생.

## 4. 담당자 인수인계 체크리스트

각 Pi 인수 시 아래 6개를 체크한다.

1. Hostname이 배정표와 일치한다.
2. 고정 IP가 배정표와 일치한다.
3. API/Edge 헬스체크가 통과한다.
4. 웹 로그인과 영상 재생이 가능하다.
5. Kibana에서 해당 IP 로그가 확인된다.
6. `/health`만 호출하고 로그가 없다고 오판하지 않는다.
