# 07. 공격 시나리오 (A1~A6)

> 갱신일: 2026-04-19  
> 역할: 운영/실험 공통 기준 문서  
> 참고: 기존 재설계 문서의 핵심 배경/매핑 내용은 본 문서에 통합했다.

---

## 1. 문서 역할

이 문서는 공격 시나리오의 **실행 기준 정본**이다.

1. 수집 라벨(`scenario_id`, `label`) 기준
2. 시나리오별 핵심 메커니즘
3. 탐지 모델(규칙/ML/GNN) 적용 경계

## 3. 시나리오 상세 요약

### A1. Credential Stuffing

공격 흐름:

1. 유출 credential 확보
2. `/api/auth/login` 자동화 시도
3. 성공 계정으로 `/api/playback/start` 즉시 호출
4. 발급 토큰을 A2/A3 인프라로 전달

탐지 포인트:

- 로그인 시도 폭증
- 로그인 직후 비정상적으로 빠른 재생 시작
- browse 과정 부재

### A2. IPTV 미들웨어

공격 흐름:

1. 탈취 계정 풀 확보(수백~수천)
2. 불법 구독자 요청을 계정별 분산
3. 계정당 동시 세션 제한은 정상 범위 유지
4. 토큰 만료 시 자동 재발급

탐지 포인트:

- 개별 세션은 정상처럼 보이나 계정군 패턴이 동기화됨
- 콘텐츠 집중도 과도
- 지역/ASN 이동 패턴 비정상

### A3. Signed URL 핫링킹

공격 흐름:

1. 합법 계정으로 토큰 URL 획득
2. 텔레그램/불법 사이트로 URL 공유
3. 다수 클라이언트가 동일 토큰으로 CDN 직접 접근

탐지 포인트:

- 동일 token/session의 다중 IP fan-out
- 비브라우저 UA 비율 증가
- referer 비정상 또는 공란

### A4. Residential Proxy 릴레이

공격 흐름:

1. 토큰 발급 후 프록시 네트워크 경유
2. CDN 수신 세그먼트를 외부 재배포
3. 토큰 갱신으로 장시간 지속 운영

탐지 포인트:

- 장시간 연속 세션
- 요청 간격의 과도한 기계성
- seek/pause가 거의 없는 선형 소비 패턴

### A5. DRM/앱 취약점 악용

경로 A:

- DRM 복호화 후 외부 재배포
- CDN 로그 단독 탐지 불가

경로 B:

- 앱 역공학 후 세그먼트 직접 요청 자동화
- 매니페스트 부재/빈 referer/비정상 간격으로 탐지 가능

### A6. 라이브 이벤트 동시 탈취

공격 흐름:

1. 이벤트 직전 다수 계정 활성화
2. 라이브 토큰 발급 및 공유
3. 이벤트 구간 동시 대량 접근
4. 종료 직후 트래픽 급락

탐지 포인트:

- 이벤트 시작 직후 세션/요청 급증
- 동일 토큰 공유 IP 수 증가
- 비브라우저 UA, 빈 referer 비율 증가

## 5. 라벨/수집 실행 규칙

수집 시 다음 메타데이터를 함께 전달한다.

1. `label` (정본)
2. `run_id`
3. `scenario_id`
4. `dataset_label` (호환 별칭)

예시:

- `label=attack_A2`
- `run_id=20260419_r01`
- `scenario_id=A2`

초기화/라벨 삽입/검증 절차는 `15_데이터_초기화_및_수집_운영_가이드.md`를 기준으로 한다.

## 6. 실증랩 재현 범위
