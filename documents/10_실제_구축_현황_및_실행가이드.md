## 1. 실제 디렉토리 매핑

| 역할 | 실제 디렉토리 | 비고 |
|------|--------------|------|
| DB 초기화 | `database/` | PostgreSQL 스키마 + 시드 계정 |
| Origin 서버 | `origin/` | Nginx + HLS 파일 + 사용자 웹 UI |
| Edge/API 게이트웨이 | `scrubber/` | OpenResty Gateway + Auth/Playback API + 콘솔 |
| 탐지 엔진 | `detection/engine/` | Dockerfile이 `main_v5.py`를 `/app/main.py`로 복사해 실행 |
| 로그 수집(로컬) | `log-system/` | 로컬 통합 스택용 Filebeat 설정 |
| 통합 오케스트레이션 | `docker-compose.lab.yml` | 로컬 전체 스택 1회 기동 |

라이브 확장 구성:

- `origin/source/`: live-encoder 입력 소스(`sample.mp4`) 보관
- `live-encoder` 서비스: `origin/hls/live_001/`에 1080p/720p 라이브 HLS 생성

VOD 업로드 확장 구성:

- `/manage`에서 `sourceVideo`를 업로드하면 `scrubber/api`가 FFmpeg로 `origin/hls/<hls_path>/`에 1080p/720p VOD HLS와 `master.m3u8`를 자동 생성
- `/manage`에서 `target_duration_min`을 함께 지정하면, 짧은 원본 영상을 반복 확장하여 목표 길이 VOD를 생성
- API 직접 호출 시에는 `target_duration_sec` 또는 `target_duration_min`으로 동일 기능 사용 가능
- 자동 생성은 `content_type=vod`일 때만 수행되며, `live` 타입은 기존 라이브 인코더 경로를 사용

## 3. 인증/재생 토큰 실제 동작

주요 엔드포인트:

1. `POST /api/auth/login`
2. `POST /api/playback/start` (탐지 kind: `playback_start`)
3. `GET /api/browse/content/:contentId` (탐지 kind: `browse_content`)
4. `POST /api/playback/verify` (Gateway Lua 내부 호출)
5. `GET /api/user/watch-history` (서비스 기능용, 탐지 kind 분류 대상 아님)
6. `GET /api/browse/search` (서비스 탐색 API, 탐지 분류의 핵심 kind에는 미포함)

탐지 엔진의 `Request.kind` 분류 기준:

- `playback_start`
- `browse_content`
- `hls_manifest`
- `hls_segment`

운영 기준:
- `playback_start`, `browse_content`는 Edge/Gateway의 `/api` 요청 로그에서 분류된다.
- 따라서 웹/클라이언트 API 기본 진입점은 Gateway(로컬 `:8081`, 분산 Edge IP)여야 한다.

재생 흐름:

1. 웹 UI 로그인 후 JWT 획득
2. 시청 진입 시 `playback/start` 호출
3. API가 Signed URL(`token`, `sig`) 생성
4. Gateway Lua(`scrubber/lua/auth_check.lua`)가 HLS 요청마다 `playback/verify` 호출
5. 검증 성공 시 Origin으로 프록시

토큰 payload 핵심 필드: `uid`, `sid`, `cid`, `path`, `edge`, `iat`, `exp`

플랫폼 확장:

- 홈 화면에서 콘텐츠(VOD)/라이브(LIVE) 카테고리 분리
- `/manage` 영상관리 페이지에서 콘텐츠 메타데이터 등록/업데이트 및 파일 업로드
- VOD 업로드(`sourceVideo`) 시 API가 업로드 직후 FFmpeg로 1080p/720p HLS + `master.m3u8` 자동 생성
- 콘텐츠 메타데이터의 해상도(`1080p`, `720p`)는 자동 생성 결과 및 시청 페이지 화질 선택 UI와 연동

## 4. 로그/탐지 동작 (모드별)

### 4.1 로컬 단일 머신 모드 (`docker-compose.lab.yml`)

1. `scrubber-gateway` JSON access log(`/api`, `/hls`) 생성
2. `scrubber_logs` 공유 볼륨을 `detection-engine`이 `/var/log/scrubber`로 읽음
3. Filebeat가 Gateway/Origin 로그를 Elasticsearch로 전송
4. Detection이 Neo4j에 노드/관계를 MERGE

### 4.2 물리 분산 모드 (`deploy/server4/docker-compose.yml`)

1. Edge Pi의 Filebeat가 중앙 Elasticsearch(192.168.0.120)로 로그 전송
2. 서버#4 Detection이 `LOG_SOURCE=elasticsearch`로 ES 인덱스를 poll
3. Detection이 Neo4j(192.168.0.120, DB=`neo4j`)에 적재

## 7. 코드/실행 기준 정리

1. Detection 실행 엔트리포인트는 `main_v5.py` 기반이다.
2. 실제 컨테이너 실행 파일명은 `/app/main.py`이며, Docker 빌드 시 `main_v5.py`가 복사된다.
3. `main.py`, `main_v2.py`, `main_v3.py`, `main_v4.py` 등 구버전 파일은 저장소에 남아 있을 수 있으나 현재 기본 실행 경로가 아니다.
4. 분산 모드에서 Neo4j 적재 확인 시 `NEO4J_DATABASE=neo4j` 기준으로 조회한다.
5. `scrubber/api` 컨테이너에는 FFmpeg가 포함되어 있으며, `/api/content/admin/upload`의 VOD 업로드 시 서버에서 HLS 트랜스코딩을 수행한다.
