# 13. 엣지 라즈베리 개별 운용 설명서 (edge-kr/jp/sg/us)

이 문서는 Edge Pi 4대를 각각 독립 CDN Edge로 운용하기 위한 장비별 실행 카드다.

---

## 0. 공통 기준

- API/Origin 서버: `192.168.0.100`
- Elasticsearch/Neo4j/Kibana 서버: `192.168.0.120`
- Detection 서버: `192.168.0.130`
- 서브넷: `192.168.0.0/24`
- 게이트웨이: `192.168.0.1`
- DNS: `8.8.8.8`
- 클라이언트 API 기본 진입점: 각 Edge URL의 `/api` 경로

Edge 분리 원칙:

- Edge Pi 1대당 Edge 컨테이너 1개만 실행
- 각 Edge Pi에서 Filebeat가 로컬 edge 로그를 중앙 Elasticsearch로 전송

## 2. 공통 1회 설정 (모든 Edge Pi)

```bash
sudo apt update
sudo apt install -y git curl ca-certificates
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
newgrp docker
```

코드 배치:

```bash
git clone <YOUR_REPO_URL> ~/OTT_Testbad
cd ~/OTT_Testbad
```

Filebeat 점검 기본 원칙:

- Edge compose의 filebeat는 `-strict.perms=false`로 실행된다.
- 컨테이너 내부 수동 점검 시에도 동일 옵션을 사용한다.
	- `docker exec -it filebeat-edge-kr filebeat -strict.perms=false test config`
	- `docker exec -it filebeat-edge-kr filebeat -strict.perms=false test output`

## 3. Edge Pi별 실행 카드

### 3.1 edge-kr-pi (192.168.0.111)

```bash
sudo hostnamectl set-hostname edge-kr-pi
sudo tee /etc/dhcpcd.conf > /dev/null <<'EOF'
interface eth0
static ip_address=192.168.0.111/24
static routers=192.168.0.1
static domain_name_servers=8.8.8.8
EOF
sudo systemctl restart dhcpcd

cd ~/OTT_Testbad/deploy/edge-kr
docker compose up -d --build
```

검증:

```bash
curl http://192.168.0.111/health
curl http://192.168.0.111/api/content/list
docker logs edge-kr --tail 50
docker logs filebeat-edge-kr --tail 50
```

로그 유입 검증 트래픽 생성:

```bash
for i in 1 2 3 4 5; do curl -s "http://192.168.0.111/?probe=$i" >/dev/null; done
```

## 4. 운영 체크포인트

1. API 검증 연동(내부): 모든 Edge Pi에서 `http://192.168.0.100:3001/health` 접근 가능
2. API 경유 유입(클라이언트 경로): 각 Edge에서 `http://<edge-ip>/api/content/list` 응답 확인
3. 로그 수집: Kibana에서 `scrubber-nginx-*`에 edge별 로그 유입 확인
4. 탐지 적재: 서버#4 로그에서 Elasticsearch poll 성공 메시지 확인
5. 장애 격리: 특정 Edge Pi 장애 시 나머지 3개 Edge는 계속 서비스
6. `/health`는 access log가 비활성화되어 있으므로 Kibana 유입 검증은 일반 경로(`/?probe=...`)로 수행
7. 라이브 경로 캐시 검증: `live_001`의 `playlist.m3u8`은 짧은 캐시(1s), `seg_*.ts`는 장기 캐시(300s) 정책 적용 여부 확인
8. 라벨 수집 검증: access log JSON에 `token_label`, `token_run_id`, `token_scenario_id` 필드가 포함되는지 확인

라이브 확인 예시:

```bash
curl "http://192.168.0.111/hls/live_001/master.m3u8"
curl "http://192.168.0.111/hls/live_001/1080p/playlist.m3u8?token=<TOKEN>&sig=<SIG>"
docker logs edge-kr --tail 100 | grep live_001
```

라벨 필드 확인 예시:

```bash
docker exec -i edge-kr sh -lc "tail -n 20 /var/log/nginx/access.log | grep token_label"
```
